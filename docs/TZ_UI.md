# ТЗ: главный экран аналитика (viz.py → out/graph.html)

Прочитай AGENTS.md, README.md, viz.py, llm_layer.py, tests/test_viz.py, tests/test_viz_client.cjs.
Правила AGENTS.md действуют полностью. run.py, схему CSV и логику ролей НЕ трогай — задача только про интерфейс.

## Зачем
Сейчас главный экран — «клубок» из ~700 узлов. Он не отвечает на вопрос кейса
«кого из 2 248 клиентов смотреть первым и почему»: топ-листа на экране нет, обоснование
спрятано в тултипе, легенда на техническом языке. Нужен экран, который жюри понимает за 3 секунды.

## Макет: шапка + три колонки, тёмная тема (как сейчас)
```
┌───────────────────────────────────────────────────────────────────┐
│ FuryHub · Граф денег    81 → 2 248 → 25                 [Вся сеть] │
├──────────────┬──────────────────────────────┬─────────────────────┤
│ [поиск]      │ Окружение …3684369100  [←Назад]│ ● Координатор  66% │
│ КОГО ПРОВЕР. │ ← кто платит     кому платит → │ бейджи, числа,     │
│ 1 ● Коорд.   │ [плашки]  →  ●  →  [плашки]    │ почему в списке,   │
│ 2 ● Транзит  │ +N ещё, суммой X ₸             │ подсказка LLM,     │
│ ...          │ легенда в 1–2 строки           │ плательщики/получ. │
└──────────────┴──────────────────────────────┴─────────────────────┘
```
Колонки: 340px | остаток | 390px. Каждая колонка скроллится сама, страница целиком — нет.

### 1. Шапка — воронка
- Три крупных числа (30px): число seed → число узлов → число строк top_nodes.csv.
  Подписи: «известны из дела» → «в сети переводов» → «на проверку». Третье число — акцентным цветом.
- Все числа — из данных, не хардкод.
- Справа кнопка «Вся сеть» (min-width 160px, чтобы шапка не прыгала). В режиме обзора она
  подсвечена и называется «← К окружению».

### 2. Левая колонка — очередь проверки
- Поиск сверху. Принимает полный gid ИЛИ его последние цифры (от 4). Если хвост однозначен — выбрать узел;
  если совпадений несколько — «Найдено N gid на …1234 — введите больше цифр»; нет — «не найден». Ошибка красным.
  После успешного поиска: «Найден: №5 в очереди проверки» или «Найден: транзит, вне топа».
- Заголовок «КОГО ПРОВЕРЯТЬ ПЕРВЫМ», ниже top_nodes.csv по rank: номер, цветная точка роли,
  роль по-русски, укороченный gid справа, вторая строка — why с многоточием (полный текст в title).
- Клик / Enter по строке → узел выбран, строка подсвечена и прокручена в видимую область.
- При открытии выбран ранг 1.

### 3. Центр — окружение выбранного узла (самое важное)
- Только выбранный узел и соседи на 1 шаг. Рёбра рисуем только между центром и соседями.
- Раскладка слева направо по движению денег: плательщики — колонка слева (x = −450),
  центр — (0,0), получатели — колонка справа (x = +450), шаг по вертикали 64.
  Узлы, которые и платят, и получают, — ряд сверху над центром, по две изогнутые стрелки (туда и обратно).
- Соседи — ПЛАШКИ (shape: box), не точки: текст «…3880331100   320 тыс ₸» (сумма жирным),
  шрифт 27 в координатах графа, min-width 300, заливка — цвет роли с прозрачностью ~0.22,
  рамка — цвет роли; у seed рамка белая. Для встречных: «…gid» + «← 200 тыс ₸ · 200 тыс ₸ →».
- Центр — крупная точка (size 44) цвета роли, подпись «…gid · №N» (номер, если в топе), шрифт 30.
- Лимит: 12 крупнейших по сумме с каждой стороны, 5 встречных. Остальное — строкой под графом:
  «+84 получателей ещё, суммой 12,9 млн ₸ (показаны крупнейшие)». Проверено: при 30 на сторону
  подписи на проекторе нечитаемы.
- Рёбра прямые, толщина 1 + 6·log1p(сумма)/log1p(макс. суммы). Входящие — синеватые (#6f93c4),
  исходящие — оранжевые (#d9a45f). Tooltip ребра: «…a → …b / 1,2 млн ₸ · 3 перевода».
- selectConnectedEdges: false и hoverConnectedEdges: false — иначе при выборе центра все рёбра желтеют.
- После fit: если scale > 0.8, сделать moveTo({scale: 0.8}) — иначе у узла с 2–3 соседями текст огромный.
- Над графом полупрозрачные подсказки «← кто платит» и «кому платит →». Сверху строка:
  «Окружение …gid · 24 плательщика слева, 62 получателя справа» (одна строка, с многоточием) и кнопка «← Назад».
- Клик по соседу → он становится выбранным (история для «Назад»).
- Изолированный узел: только центр и строка «Видимых переводов у этого клиента нет».
- Физика выключена, координаты детерминированные.

### 4. Режим «Вся сеть»
- Текущий обзор (топ-50 + прямые соседи, spring_layout в Python) — вторичный режим.
- Клик — обновить карточку, двойной клик — открыть окружение. «← К окружению» — вернуться к выбранному.
- Флажок «кто платит / кому платит» в этом режиме скрыть.

### 5. Правая колонка — карточка
- Роль по-русски (22px) + «уверенность NN%» (role_score); строкой ниже — смысл роли:
  координатор — «связывает несколько групп, кандидат в организаторы»; распределитель — «раздаёт деньги многим
  получателям»; консолидатор — «собирает деньги от нескольких участников»; транзит — «пропускает деньги дальше,
  не удерживая»; конечный получатель — «деньги приходят и остаются»; периферия — «признаков роли не выявлено».
- Полный gid моноширинным + кнопка «копировать».
- Бейджи: «№N в очереди проверки»; «из списка по делу (seed)» (белая рамка);
  «обход оборвался на 4-м шаге: дальнейшие переводы не видны» (жёлтый); «N-й шаг от известных клиентов»; «группа K».
- Две плитки: «Получил 3,8 млн ₸ / от 24 плательщиков · 58 переводов» и «Отправил 8,6 млн ₸ / 62 получателям · 67 переводов».
- Строка про пропуск: при out/in ≤ 1.5 — «Передаёт дальше 13% полученного»; при > 1.5 —
  «Отправил в 2,2 раза больше, чем видно на входе»; при нулевом входе — «Входящих переводов в выборке нет».
  Для seed серым: «у клиентов из дела входящие занижены: выгрузка собрана от них»;
  для обрезанных: «нулевой выход не доказывает, что деньги осели».
- «ПОЧЕМУ В СПИСКЕ» — why из top_nodes.csv (для узла вне топа — evidence).
- «ПОДСКАЗКА АНАЛИТИКУ» (только у топа): «На что обратить внимание: …», «Следующий запрос: …».
- «КРУПНЕЙШИЕ ПЛАТЕЛЬЩИКИ» / «КРУПНЕЙШИЕ ПОЛУЧАТЕЛИ» — до 5, точка роли, …gid, роль, сумма; клик выбирает узел.
- Внизу мелко: «Роль — гипотеза для проверки по видимой части переводов, а не утверждение о виновности».

### 6. Подсказки LLM — одним пакетом
- В llm_layer вынеси сборку payload из explain_node в функцию node_payload(nodes, edges, gid)
  (explain_node вызывает её — кеш-ключи не должны измениться) и добавь метод
  LLMLayer.node_hints(payloads) → [{"attention": ..., "next_request": ...}] через _select("node", ...).
- viz.py один раз читает CSV/parquet, собирает payload для 25 узлов топа и делает ОДИН вызов node_hints
  (а не 25 запросов). Любая ошибка — экран без блока подсказок, не падение.
- Без ключа/интернета работает локальный фолбэк. Флаг --no-llm — собрать без подсказок.

## Укороченный gid — только уникальный
В данных все gid заканчиваются на «100», поэтому последние 6 цифр НЕ уникальны (всего ~1000 вариантов).
Длину хвоста считать из данных: минимальная длина суффикса, при которой все gid различимы
(на текущих данных — 10: «…3684369100»). Передавать в страницу как shortLen.

## Язык и оформление
- Суммы: «4,2 млн ₸», «393 тыс ₸», «850 ₸». Склонения: «1 перевод / 3 перевода / 5 переводов».
- На экране нет: priority_score, role_score, pass_through, «log(1 + сумма)», «∝», англ. названий колонок.
- Легенда внизу центра в 1–2 строки: точка + название роли, смысл роли — в title; плюс «белая рамка — клиент из дела».
- Шрифт в топ-листе и карточке ≥ 14px. Проверить на 1440×900 и 1920×1080: ничего не обрезано, кнопка «Назад» в одну строку.
- Правило CSS [hidden]{display:none!important} — иначе элементы с display:flex не скрываются.

## Техника
- Один самодостаточный HTML без сервера и интернета. vis-network берётся из пакета pyvis
  (Network().templateEnv.loader.get_source(... 'lib/vis-9.1.2/vis-network.min.js' и .css)).
- Не рендерить страницу через Jinja: в CSS встречается «{#» (например «{#app»), Jinja падает с
  «Missing end of comment tag». Вставлять библиотеку и данные простым str.replace плейсхолдеров.
- Данные — один JSON (const DATA = ...;) с экранированием <, >, &, U+2028/2029. gid — только строки.
- Весь текст из данных — через textContent/createElement, без innerHTML.
- Генерация ≤ 30 с, HTML ~2 МБ.
- Флаги: --gid (открыть экран с этим узлом, неизвестный gid → ошибка и код 1), --cluster (стартовать в «Вся сеть»
  на этой группе), --no-llm, пути --nodes --edges --top --output.

## Приёмка
1. python run.py --data data --out out && python viz.py — без ошибок и без ключа OpenAI.
2. Открываю out/graph.html: воронка, очередь, выбран №1, плашки соседей читаются на 1440×900.
3. Клик по строке топа — центр и карточка меняются мгновенно.
4. Ввожу последние 10 цифр gid не из топа — узел открывается.
5. «Вся сеть» → двойной клик по узлу → окружение → «Назад».
6. python -m unittest discover -s tests -v и node tests/test_viz_client.cjs — зелёные.
7. Коммит по AGENTS.md: «Новый главный экран: воронка, очередь, окружение и карточка узла».
